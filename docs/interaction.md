# 操作与兼容性说明

## 日常操作

左键顶部控制图标打开虚拟菜单，点击副本可打开对应应用的原生菜单。虚拟条较长时可横向滚动。

右键虚拟图标可选择“打开原生右键菜单”或“从虚拟菜单移除”。移除只排除副本，不退出原应用，也不删除它的原生菜单项。身份明确的移除记录会保留；可通过顶部右键菜单中的“恢复已移除的虚拟菜单项”恢复。

“调整菜单显隐”中的蓝线左侧代表原生显示，右侧代表隐藏。跨线拖动会改变真实菜单项的分组；编辑器中的右键菜单也支持移除副本。

## 临时显示与收回

虚拟菜单展示的是图标副本，点击时仍操作真实菜单项：

1. 目标已在当前显示器可见区时，读取其当前窗口坐标直接点击。
2. 隐藏或溢出的目标会单独移入可见区。位置连续稳定后即可点击，不要求它紧挨某个固定图标；正式布局调整仍要求确认相邻关系。
3. 拖拽与点击连续完成，中途不将鼠标送回虚拟菜单。点击成功后，鼠标留在原生菜单处。
4. 临时显示的图标不会仅因弹窗消失而自动收回；再次点击该真实图标可重试打开菜单。
5. 鼠标移出图标和已识别菜单、子菜单的整个范围约 0.8 秒后可结束交互；返回菜单会取消这次移出收回。外部点击或 Esc 也可请求结束，待菜单关闭后恢复原位置。

若无法识别自定义菜单的范围，只等待外部点击或 Esc，避免将鼠标进入菜单误判成离开。检测用户点击时等待鼠标释放，不在按住期间移动图标；程序转发的点击不计为用户结束交互。

坐标按窗口实时读取，不永久缓存固定屏幕位置。显示器切换、菜单栏布局变化时，旧坐标可能已不再对应目标。

## 已知兼容性与排查

### Macshot 首次菜单可能立即关闭

2026-10-15 用户确认：整体交互可接受；Macshot 的菜单首次打开仍可能关闭，再点一次真实图标即可打开。本版保留临时显示的图标作为重试入口，这一兼容性问题尚未完全解决。

### 问号、显隐调整或刷新失效

先检查系统设置中的屏幕录制、辅助功能，以及“菜单栏 → 允许在菜单栏中显示 → wd-ice-bar”。菜单栏允许开关关闭时，程序可能存在却没有可用的控制项窗口。

权限正常时可用顶部右键菜单中的“刷新应用”重新取图。补采期间可能短暂出现原生图标；仍无法取图时保留历史图像或已确认应用的图标，无法确定时显示问号，不虚构应用身份。

本版过滤宽高为零的宿主残留，并支持双屏下高度、偏移方向不同的图标副本配对，避免将副本或残留窗口展示成额外项目。

### 顶部入口被挤出屏幕

按 **Control + Option + Command + I**（⌃⌥⌘I），或在 Finder 中重新打开正在运行的 `wd-ice-bar.app`，调出独立控制窗口。可从中打开虚拟菜单、清理测试项或退出。

`wd-ice-bar-overflow-probe` 是开发阶段的独立溢出探测程序；系统设置中可能保留它的允许记录，不需要为正常使用开启它。

## 开发验证

```bash
swift test --disable-sandbox
```

2026-10-15 当前版本通过 34 项测试，覆盖双屏副本配对、零尺寸过滤、真实项目保留、稳定可见位置确认、合成事件过滤和用户驱动收回。这些测试不能代替所有第三方菜单的实机验证；Macshot 的实际限制见上文。

手动溢出验证入口：顶部右键菜单 → “菜单栏溢出验证…”。逐步添加 T01、T02 等真实可点击测试项，测试窗口中的原生点击回执用于确认转发结果。“清理全部”、关闭测试窗口或退出应用会移除测试项；重启不会自动创建。

以下集成脚本会短暂创建真实菜单栏项，并操作这些测试项。菜单栏入口可能因此被挤出屏幕，可用前述快捷键或 Finder 恢复控制入口；日常使用无需运行：

```bash
./scripts/verify-menu-bar-overflow.sh
./scripts/verify-menu-bar-overflow.sh --native-menu
./scripts/verify-menu-bar-overflow.sh --controller
```

此前的环境、输出和能力边界保留在[溢出验证记录](overflow-feasibility.md)中，历史结果不代表当前版本已重新完成全部实机测试。
