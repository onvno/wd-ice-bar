# wd-ice-bar

轻量的 macOS 菜单栏图标管理工具：将一部分第三方状态栏图标隐藏到自定义栏，并在需要时恢复原生图标进行左键、右键和显隐调整。

![](./docs/bar-wd.gif)

[一篇内容整理](./docs.desc.md)

## 功能

- 透明宽分隔项将其右侧状态栏图标挤出可视菜单栏；
- 左键顶部控制图标，展开隐藏图标的自定义栏，并收录当前显示器可见区域之外的溢出项；
- 使用 ScreenCaptureKit 获取可见菜单栏的真实图像并缓存；缺图项目可临时移入可见区补采，后续展示复用缓存；
- 仍无法截取时保留历史图像或真实应用图标；都不可用时，真实项目仍保留并明确标记“应用身份及图像暂不可用”，不生成字母占位图；
- 模拟拖拽期间保护并恢复指针；普通原生菜单点击成功后，鼠标留在原生菜单处，不立即回跳虚拟图标，避免菜单自动关闭；真实输入更新恢复位置，按住或持续移动时暂不自动拖拽；
- 在自定义栏中左键打开原生应用；右键选择“打开原生右键菜单”或“从虚拟菜单移除”；
- 在“调整菜单显隐”中右键图标，也可直接移除；移除仅排除虚拟条和编辑器中的副本；
- 移除记录随刷新保留，能确定应用标识和窗口标题的项目保存记录，重启后继续生效；身份不明确的项目只在当前运行期间排除；
- 顶部控制图标右键 → “恢复已移除的虚拟菜单项”可恢复全部排除项；
- 右键“调整菜单显隐”，可将副本图标跨蓝线拖动：左侧显示在原生栏，右侧隐藏；
- 刷新应用、开机启动、系统菜单管理入口与图标切换。

## 手动验证菜单栏溢出

右键顶部控制图标 → **菜单栏溢出验证…**，逐步点击“添加 5 个”或“添加 10 个”。这些是带 T01、T02…编号的真实、可点击菜单栏项；不是虚拟栏自己生成的占位按钮。

测试窗口中的“打开虚拟菜单”会重新读取窗口列表并展示隐藏和自然溢出的项目。即使顶部控制图标也被挤出屏幕，这个窗口仍能打开虚拟菜单或“清理全部”。项目多时虚拟条可横向滚动。

点击项目后，测试窗口会显示对应编号的**原生点击回执**。只有真实 NSStatusItem 的按钮动作才增加回执计数；虚拟按钮本身不会伪造点击成功。屏幕外项目会先单独移动到当前显示器的可见区域，再发送带 WindowID/PID 的原生点击；测试回执收到后恢复原位置。移动、点击或恢复失败会明确报告。普通原生菜单在外部点击或 Escape 后恢复位置。

“清理全部”、关闭测试窗口或退出应用，都会移除全部测试项。重启后不会自动创建测试项。

测试项按控制项的记忆位置放到其左侧，不再全部竞争最右侧位置。菜单栏入口仍可能受其他应用和不同显示器布局影响，因此保留独立恢复入口：

- 按 **Control + Option + Command + I**（⌃⌥⌘I）调出控制窗口；如果快捷键被其他应用占用，窗口会提示。
- 在 Finder 中重新打开正在运行的 `wd-ice-bar.app`，也会调出控制窗口；不会启动第二组测试项。
- 控制窗口保持浮动，并出现在鼠标所在显示器上，可打开虚拟菜单、清理测试项或清理并退出。

## 构建与运行

在 Xcode 中打开 `Package.swift`，运行 `WDIceBar` target；或执行：

```bash
./scripts/build-app.sh
open build/wd-ice-bar.app
```

可用 `WD_ICE_BAR_SIGNING_IDENTITY` 指定签名证书；默认使用本机第一个 Apple Development 证书。

首次运行需要在“系统设置 → 隐私与安全性”中授权：

- **屏幕录制**：读取各状态栏项的图像，用于自定义栏显示；
- **辅助功能**：转发原生左键、右键，以及在编辑器中模拟 `⌘` 拖拽。

改名后的 `wd-ice-bar` 会被 macOS 视为新应用，因此需重新授权以上权限，并重新设置开机启动与顶部图标位置。

## 实现边界

wd-ice-bar 使用公开的窗口列表/截图与输入事件 API，并依赖私有 WindowServer 菜单栏窗口枚举来识别状态栏项。这使其能处理被挤出屏幕的图标，但该私有接口可能随 macOS 升级变化。详见 [Ice 实现对照](docs/ice-comparison.md)。

## 集成验证

`./scripts/verify-menu-bar-overflow.sh` 短暂创建 24 个真实测试项，并检查：正常应用项目是否丢失、屏幕外目标能否移入可见区域、原生按钮是否收到点击、能否恢复原位置。只点击和移动测试项；完成自动清理，30 秒超时也自动退出。没有辅助功能权限时跳过点击并报告，不主动请求授权。

2026-10-14 本机结果：`baseline=9 missingAfterFill=0`、`temporarilyMoved=true routed=true nativeReceipts=1`、`RESTORE 已移动`。这不等同于所有第三方菜单和多显示器组合均已验证。


### 问号与鼠标跳动的验证

首次运行先采集可见图像；虚拟菜单首次遇到缺图项目会补采一次。右键顶部图标 → “刷新应用”可再次尝试补齐，恢复过程中可能短暂出现原生图标。点击已采集的图标不会为截图重复补采。

2026-10-14 真实测试新增结果：`capturedVisible=6 targetHasRealImage=true`、`nativeReceipts=1`、`RESTORE 已移动`；静止鼠标时，`maxRestoreError=0.94`、`displacementAfterRoundTrip=0.94 hardwareMoves=0`（CoreGraphics 坐标点）。有真实鼠标输入时尊重最新输入位置，不强行恢复整个菜单打开之前的旧位置。


### 原生菜单打开后立即关闭的回归验证

`./scripts/verify-menu-bar-overflow.sh --native-menu` 创建真实 NSStatusItem 下拉菜单，点击后等待 750 毫秒检查菜单生命周期，再主动关闭并恢复项目位置。本机结果：`NATIVE_MENU opens=1 closesBeforeDismiss=0`、`RESTORE 已移动`。此模式不要求指针回到虚拟图标原位置；普通菜单操作将指针留在原生菜单处。测试项的无菜单回执模式仍会恢复原指针位置。

### 单项临时展示与完整控制流程回归

点击虚拟图标时保持宽分隔条，只将选中的原生图标移到可见侧；菜单结束后按原相邻项恢复隐藏。关闭监听忽略本程序合成的鼠标事件，并用操作代次丢弃旧的延迟关闭任务。原生菜单可能在内部消费 Escape 或选项点击，因此同时跟踪新出现的菜单/弹窗窗口，窗口关闭后再恢复图标；界面仍打开时不提前移动图标。

`./scripts/verify-menu-bar-overflow.sh --controller` 使用真实控制器创建 24 个隐藏测试项，验证一次点击打开菜单并保持 2.2 秒、另外 23 项仍隐藏、Escape 关闭后目标恢复隐藏。此模式覆盖实际激活、关闭监听与恢复逻辑，测试结束自动清理；独立测试控制项使用不同名称，不改动正式应用控制项的记忆位置。
